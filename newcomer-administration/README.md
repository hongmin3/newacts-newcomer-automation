# 새가족 교적·주보 도우미 (개발 중)

시트에 등록카드를 수기로 입력한 뒤 담당자가 직접 실행하는 Windows 프로그램입니다. 명단 검토와 주보 계산·저장 보호 코드를 작성했으며, 실제 계정 연결과 운영 반영 검증은 아직 남아 있습니다. 예약 실행은 설치하지 않습니다.

## 현재 확인한 실행

프로젝트 루트에서 다음 명령을 실행합니다.

```powershell
powershell -NoProfile -File newcomer-administration/run.ps1 doctor
newcomer-administration/.venv/Scripts/python.exe -B newcomer-administration/tests/run_tests.py
```

이 PC에서 Python 3.13.17과 전용 환경 설치, 준비 상태 확인, 합성·로컬 시험 49개 통과를 확인했습니다. 실제 Google·디모데 인증은 아직 연결하지 않았습니다.

담당자 화면은 `run.ps1`에 인자 없이 실행하도록 구현했습니다. 현재 화면은 Google 연결, 시트/CSV 불러오기, 디모데 인증과 교적 대조, 검토 자료 저장을 제공합니다. 실제 사용자 화면 검수는 남아 있습니다.

## 연결 준비

Google Desktop OAuth JSON은 저장소 밖에 보관하고 ‘Google 연결’에서 선택합니다. Google Sheets API 활성화와 테스트 사용자 등록, 브라우저에서 읽기 권한 승인, 실제 시트 읽기 확인이 필요합니다. JSON 발급과 로그인 토큰 발급은 서로 다른 단계입니다.

디모데 인증은 PC 입력창에서 받으며 Windows 현재 사용자 DPAPI로 암호화합니다. 로그인 실패 후에는 자동 재시도하지 않습니다. 원문 문서의 계정·암호를 코드나 설정 예제에 넣지 않습니다.

## 검토와 주보 원칙

- 일반 등록 시트를 기본 원본으로 사용합니다. 사용자가 등록 기간과 이후 주보 발행일을 직접 지정합니다.
- 방문 전용은 제외합니다. 기등록자는 교적을 새로 만들지 않지만 주보·새 번호·전도 실적에 포함합니다.
- 고정 관리번호·필수값·동일인 판단·인도자 정책이 확인되지 않으면 해당 반영을 보류합니다.
- 승인 뒤 원본·기준 수치·양식이 바뀌면 다시 확인합니다. 결과 불명 저장은 재조회 전 재전송하지 않습니다.
- 한글은 작업 사본에서 편집하고 다시 읽어 대조합니다. 기존 최종본은 덮어쓰지 않습니다.

## 아직 사용할 수 없는 부분

운영 교적 writer는 활성화하지 않았습니다. 실제 신규 등록 화면과 저장 후 재조회 연결이 필요합니다. 고정 관리번호 발급과 실제 정렬 추적, 시트 변경, 한글 양식 연결과 실제 저장·재열기·페이지 확인, 공유 시험 폴더 검증, 담당자 화면의 승인부터 최종 저장까지 통합도 남아 있습니다.

실제 다음 주 한글 사본에서는 마지막 번호·총계 차이와 인도자 이름 중복을 발견했습니다. 자동으로 수치나 사람을 정정하지 않습니다. 합성 시험 통과는 운영 저장 확인을 뜻하지 않습니다.

현재 사양과 상세 계획은 [기능 사양](../specs/newcomer-administration.md), [구현 계획](../docs/superpowers/plans/2026-10-26-newcomer-administration.md), [진행 상태](../progress.md)를 참조합니다.
