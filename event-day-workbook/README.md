# 11월 1일 행축 명단

전체 방문·전체 등록과 군별 명단을 연결한다. 방문 카드와 등록 카드를 각각 입력하며 등록을 적어도 방문에는 자동 추가하지 않는다. 같은 분을 양쪽에 각각 입력하면 방문 1건·등록 1건으로 따로 센다.

- 순번은 각 명단에서 이름이 있는 행의 화면 순서대로 자동으로 매긴다. 번호를 직접 바꾸거나 이름을 지우면 다시 정리한다.
- 방문 명단의 `순`은 `-`로 표시한다. 등록 명단의 `순`은 입력한 값을 유지한다.
- 전체 명단은 1행 머리글 아래 2행부터 입력한다.
- 군별 탭은 원본처럼 파란 제목·빨간 열 제목·테두리 표를 쓴다. 위쪽이 방문, 아래쪽이 등록이다.
- 처음에는 방문 3~22행, 등록 27~36행에 입력한다. 끝의 빈칸이 5개 이하로 남으면 10행을 더하고 등록 구역을 함께 옮긴다.
- 군 값은 `명`·`총`처럼 표시한다. `명군`과 `명` 중 어느 쪽으로 입력해도 된다.
- 총 방문·총 등록 명단에서 군을 비우면 기타가 된다. 군별 명단은 새 입력과 기존 명단 수정 모두 군이 빈칸이면 해당 탭의 군으로 배정한다.
- 각 명단의 1행 옆에는 방문자 수·등록자 수만 표시한다.
- 어느 명단에서든 보이는 명단 내용 전체를 비우면 그 카드만 같은 종류의 전체·군별 명단에서 삭제한다. 다른 종류의 카드와 집계는 유지한다. 명단 행 자체를 삭제해도 같은 카드만 연결된 명단에서 제외한다. 머리글과 계 행은 유지한다.
- 등록경로는 전체 등록·군별 등록 구역에서 `직접방문`·`설문지`·`관계`·`교인인도` 중 하나를 선택한다. 같은 사람의 다른 등록 화면에도 반영되며 새 입력 행에도 선택 목록이 유지된다.

빠르게 입력해 앞선 수정이 대기하면 다음 편집에서 같은 명단의 대기 항목을 함께 반영한다. 15초 안에 차례가 오지 않아도 입력값을 남긴다. 1분 간격의 자동 재처리가 남은 내용을 확인하므로 추가 입력이나 새로고침 없이 기다리면 된다. 같은 칸의 충돌이나 잘못된 입력은 셀 메모를 확인한다.

같은 종류의 명단에서 이름·정리한 전화번호·군·팀이 모두 같으면 기존 입력과 연결한다. 군이나 팀이 다르면 두 행을 남기고 양쪽 이름 칸을 연한 노란색으로 표시하며 중복 확인 메모를 남긴다.

방문과 등록에 각각 입력되면 양쪽에 `방문·등록 각각 입력됨` 메모를 남기고 카드별 집계 안내를 띄운다. 수정·군 이동·등록경로·삭제는 방문과 등록 사이에 전파하지 않는다. 삭제는 그 카드의 관리번호에만 적용한다.

이름만 같거나 전화번호가 없으면 임의로 합치지 않는다. 같은 칸의 수정이 겹치면 셀 메모에 저장값과 입력값을 안내한다. 내용을 확인하고 그 칸에 다시 입력하면 된다.

체크박스, 등록 비율, 결신 열, 표 버튼, 추가 메뉴와 별도 현황판은 없다. 연결 정보와 변경 기록은 숨겨 둔다. 숨겨진 열을 복사하거나 바꾸지 않는다.

이 파일의 편집자는 다른 군의 명단도 볼 수 있다. 담당자에게만 공유한다. 기존 등록·교육·메일 자동화와는 별도다.

검증은 프로젝트 루트에서 `node tests/event-day-workbook.test.js`와 `node tests/event-day-concurrency.test.js`로 실행한다. 로컬 검사는 Google의 실제 편집 이벤트와 권한을 대신 검증하지 않는다.

자동 재처리는 이 파일에 연결된 Apps Script의 `eventAutoSync`를 시간 기반·분 단위·1분마다 실행하도록 한 개 설치한다. 실행 계정은 이 명단의 편집 권한이 있어야 한다. 대기가 없으면 전체 처리를 건너뛰고, 편집 이벤트 누락을 확인하기 위해 15분마다 명단을 다시 확인한다. 다른 프로젝트의 실행 조건은 바꾸지 않는다.

이름만 비우면 수정 대기로 남고 다른 정보는 유지됩니다. 삭제하려면 해당 사람의 A~L열(방문) 또는 A~M열(등록) 내용을 함께 비우세요. 이름만 쓰인 기록은 이름을 비우면 삭제됩니다. 행 자체를 삭제해도 같은 카드만 삭제됩니다. 여러 행을 함께 지울 수 있으며, 방문을 삭제해도 등록 카드는 남습니다. 머리글·계·열·탭은 삭제하지 마세요.

입력 대기는 자동으로 다시 처리합니다. `충돌`·`입력 확인`·`이름 수정 대기` 메모는 확인과 수정이 필요합니다. 전화번호가 없거나 다르면 같은 분의 방문·등록 여부를 자동 확정할 수 없습니다. 여러 담당자는 각자 다른 빈 행을 사용하세요. 같은 칸의 편집은 확인 메모가 남을 수 있습니다.

각 군 방문·등록 구역은 끝의 빈칸이 5개 이하로 남으면 10칸씩 미리 늘어납니다. 방문 구역 확장 시 아래 등록 구역도 함께 이동하며 입력값과 선택 목록을 유지합니다.

이름의 글자색으로 입력 상태를 구분합니다. 빨강은 충돌 확인, 주황은 입력 확인, 파랑은 자동 반영 대기입니다. 이름 칸 메모에 이유와 조치가 나오며, 문제를 수정하면 기본 글자색으로 돌아옵니다. 기존 노란 배경의 중복 경고는 유지합니다. 이름 머리글 메모에서도 색상 안내를 볼 수 있습니다.

표시만 다시 적용하는 `eventRefreshStatusDisplay`는 메모·이름 글자색만 갱신합니다. 입력 내용, 연결 번호, 원본, 집계 수식, 행 위치를 바꾸지 않습니다. 기존 충돌 내용의 옳고 그름을 자동으로 결정하거나 과거 충돌 기록을 일괄 해결 처리하지 않습니다.

동기화 확인은 저장이 확정된 명단의 누락부터 복구합니다. 입력이 몰리면 대기 처리를 나눠 다음 자동 확인에서 이어 가므로 같은 내용을 다시 붙여넣지 않아도 됩니다. 빨간 충돌과 주황 입력 오류는 안내에 따라 해당 칸을 확인해야 합니다.

전체 상단 인원과 각 군의 `계`는 화면에 이름을 입력한 사람 수를 바로 셉니다. 반영 대기·입력 확인 중인 사람도 포함하고, 이름이 빈칸이거나 공백만 있으면 제외합니다. 방문과 등록은 별도 계산합니다. 명단 연결이 끝났다는 뜻은 아니므로 파란 대기·빨간 충돌 메모는 따로 확인해야 합니다.

행 추가·삭제 연결은 먼저 `eventEnableStructureTracking`을 실행해 현재 관리번호를 기억한 뒤, 이 파일의 Apps Script 트리거 화면에서 `eventOnChange`를 스프레드시트의 변경 시 실행으로 한 개 설치합니다. 기존 `eventAutoSync`는 유지합니다. 처음 설정하기 전에 빠졌던 행은 삭제로 추측하지 않습니다.

기타 명단의 군 칸을 `신` 또는 `신군`처럼 바꾸면 같은 종류의 해당 군 명단으로 이동하고 총 명단의 군도 함께 바뀝니다. 처리 중 대기한 군 변경은 자동 확인에서 전체 화면 복구보다 먼저 반영합니다. 방문과 등록은 각각 이동하며 다른 입력값은 유지합니다.
