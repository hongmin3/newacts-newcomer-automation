# 행축 당일 방문·등록 시트

## 1. 목적

행사 담당자가 2026년 11월 1일에 방문자와 등록자를 적으면 전체 명단과 군별 명단에 함께 표시된다. 2025년 하반기 등록·방문 양식과 2026년 상반기 군 구분을 참고하며 과거 개인정보는 가져오지 않는다.

## 2. 범위

새 스프레드시트에 연결된 별도 Apps Script로 제공한다. 기존 등록·교육·메일 자동화의 설정과 실행 시점은 바꾸지 않는다.

## 4. 자동 실행

| 실행 | 시각·시간대 | 실행 위치 | 실행 조건 | 결과 저장 | 알림 |
|---|---|---|---|---|---|
| 대기 입력 재처리(`eventAutoSync`) | 1분 간격, Asia/Seoul | 행사 시트의 Apps Script | 대기 표시가 있거나 마지막 전체 확인 후 15분 경과 | 같은 파일의 전체·군별 명단과 숨김 원본·변경 기록 | 입력 오류·충돌은 셀 메모 |

## 5. 요구사항

| 카테고리 | 이름 |
|---|---|
| EVENTDAYWORKBOOK | 행축 당일 방문·등록 양방향 입력 |

### REQ-EVENTDAYWORKBOOK-001 행사 당일 빈 명단과 군별 구성

- 날짜는 `2026-11-01`, 시간대는 `Asia/Seoul`이다.
- 전체 방문·전체 등록·신군·조군·명군·총군·영군·석군·전군·임군·슬군·기타 탭을 제공한다.
- 전체 명단은 1행 머리글 아래 2행부터 입력한다. 군별 명단은 원본처럼 제목 줄과 열 제목 줄을 따로 둔다.
- 화면에는 전체 방문·전체 등록과 군별 명단만 둔다. 군별 명단은 방문을 위쪽, 등록을 아래쪽에 둔다. 과거 명단은 남기지 않는다.
- 군이 비어 있으면 기타로 기록한다. 군별 탭의 새 입력은 그 군을 기본값으로 쓴다.

### REQ-EVENTDAYWORKBOOK-002 전체와 군별 명단의 양방향 입력

1. 담당자는 전체 방문·전체 등록 또는 군별 탭에서 이름을 입력한다.
2. 관리번호를 자동으로 부여하고, 같은 기록을 해당하는 전체·군별 탭에 반영한다.
3. 어느 탭에서든 입력 항목을 수정하면 같은 관리번호의 기록이 함께 바뀐다. 군을 바꾸면 새 군으로 이동한다.
4. 여러 행 붙여넣기를 지원한다. 관리번호·수정시각·내부 비교값은 담당자가 바꾸지 않는다.

- 같은 종류의 명단에서 이름·정리한 휴대전화·군·팀이 모두 같은 경우만 기존 입력에 연결할 수 있다. 전화번호가 없으면 이름만으로 합치지 않는다.
- 같은 번호의 다른 이름, 연락처 누락, 동명이인은 확인할 수 있도록 표시한다.
- 이름·날짜·군·체크 값·나이·생년월일·전화번호를 검사한다. 맞지 않으면 기존 기록을 보존하고 입력 행에 이유를 표시한다.

### REQ-EVENTDAYWORKBOOK-003 방문·등록 카드별 입력·삭제와 집계

- 방문과 등록은 독립해서 입력한다. 등록 명단에 이름을 적어도 방문 명단에는 자동 추가하지 않는다. 같은 분이 방문과 등록에 각각 입력되면 서로 다른 관리번호로 보관하고 각각 한 건씩 센다. 양쪽 명단에 입력됐다는 안내와 확인 메모를 표시한다. 체크박스는 쓰지 않는다.
- 방문 명단과 등록 명단은 별도 입력 영역이다. 군별 탭의 위쪽은 방문, 아래쪽은 등록 명단이다.
- 각 명단의 1행 옆에서 방문자 수와 등록자 수만 보여 준다. 관리번호로 같은 카드를 구분한다. 비율과 별도 현황판은 만들지 않는다.
- 전체·군별 방문 또는 등록 명단에서 이름을 비우면 그 카드의 관리번호만 취소하고 같은 종류의 전체·군별 화면에서 제외한다. 다른 종류의 카드와 집계는 유지한다. 변경 전 값과 대기 중이던 입력은 숨김 변경 기록에 남긴다.
- 자동화가 쓰는 숨김 연결 열은 지우지 않는다. 행 자체를 삭제해 연결 열까지 없애면 삭제한 사람을 구분할 수 없으므로 원본에서 화면이 복구될 수 있다. 사람을 삭제할 때는 이름 또는 보이는 명단 내용만 비운다.

### REQ-EVENTDAYWORKBOOK-004 정보 차이와 입력 보존

- 같은 항목의 수정이 겹치면 저장값과 입력값을 셀 메모로 안내한다. 확인 후 그 칸을 다시 입력하면 반영한다.
- 아직 처리되지 않은 다른 입력은 화면 갱신으로 덮어쓰지 않는다. 서로 다른 항목의 변경은 합칠 수 있다. 다음 편집에서는 같은 명단의 대기 행과 항목을 함께 처리한다.
- 다른 편집이 진행 중이면 최대 15초 동안 차례를 기다린다. 그래도 처리하지 못하면 입력값을 남기고 안내한다.
- 입력을 비우거나 같은 사람으로 연결한 기록은 숨겨진 변경 기록에 남긴다. 개인정보는 저장소에 넣지 않는다.

### REQ-EVENTDAYWORKBOOK-005 기존 양식처럼 단순한 명단

- 입력 열은 순번·예배(부)·이름·성별·나이(생년월일)·휴대폰·주소·전도자·군·팀·순·비고다. 등록 명단만 등록경로를 더한다.
- 전체 명단은 1행 머리글, 2행부터 입력한다. 군별 탭은 원본의 파란 제목·빨간 열 제목·검은 테두리를 쓴다.
- 군별 방문은 1행 제목·2행 열 제목·3~22행 입력·23행 계다. 등록은 25행 제목·26행 열 제목·27~36행 입력·37행 계다.
- 방문은 처음 20명, 등록은 10명분을 가까이 배치한다. 자동 반영할 빈칸이 부족하거나 마지막 입력 칸의 다음 행에 직접 입력하면 5행을 더하고 아래쪽 등록 구역을 함께 옮긴다. 사람이 행을 더해도 이름이 지정된 입력 범위로 구역을 구분한다.
- 체크박스·결신 열·등록 비율·테이블 버튼·사용자 메뉴·별도 현황판은 표시하지 않는다. 등록경로는 REQ-EVENTDAYWORKBOOK-009의 한 칸 선택형을 사용한다.
- 내부 연결 정보와 오류 기록은 숨긴다. 화면에는 명단과 인원수만 남긴다.

### REQ-EVENTDAYWORKBOOK-006 자동 순번과 방문 명단의 순 표시

- 전체 방문·전체 등록·군별 방문·군별 등록은 이름이 있는 행에 화면 순서대로 1부터 연속 번호를 표시한다. 빈 행과 머리글·계 행에는 번호를 넣지 않는다.
- 어느 명단에서 입력·이름 삭제·군 이동·여러 행 붙여넣기·순번 직접 수정을 해도 순번을 다시 매긴다. 시트를 다시 열 때도 확인한다. 사람의 다른 입력과 행 순서는 보존한다.
- 방문 명단의 소그룹 열(`순`)은 이름이 있는 행에 `-`로 표시한다. 등록 명단의 `순`과 숨겨진 원본 값은 보존하며 방문 화면의 `-`를 등록 정보로 저장하지 않는다.

### REQ-EVENTDAYWORKBOOK-007 새로고침 없는 대기 입력 자동 반영

1. 어느 명단에서든 편집이 시작되면 재처리가 필요하다는 표시를 저장한다. 다른 입력을 기다리다가 중단돼도 이 표시를 유지한다.
2. 1분 간격의 자동 실행이 전체·군별 명단의 대기 입력을 처리하고 순번을 확인한다. 추가 입력이나 새로고침은 필요하지 않다.
3. 다른 처리가 진행 중이거나 일시적으로 실패하면 완료로 표시하지 않고 다음 실행에서 다시 시도한다. 처리 도중 들어온 편집도 다음 확인 대상으로 남긴다.
4. 편집 이벤트 자체가 누락된 경우를 위해 마지막 전체 확인 후 15분이 지나면 다시 명단을 확인한다. 대기가 없으면 매번 전체 명단을 쓰지 않는다.

- 같은 카드를 중복 추가하지 않고 REQ-EVENTDAYWORKBOOK-004의 입력 보존·충돌 안내를 적용한다. 잘못된 입력과 같은 칸의 충돌은 확인이 필요하다.
- 이 행사 시트에만 자동 실행을 하나 설치한다. 기존 등록·교육·메일 자동화의 실행 조건은 바꾸지 않는다.

### REQ-EVENTDAYWORKBOOK-008 군 값의 짧은 표시

- 전체·군별 방문과 등록 명단의 군 칸은 `신`·`조`·`명`·`총`·`영`·`석`·`전`·`임`·`슬`로 표시한다. `기타`는 그대로 표시한다.
- `명`과 `명군`처럼 어느 형태로 입력해도 같은 군으로 처리하고 화면에는 짧게 표시한다. 기존 명단도 같은 기준으로 정리한다.
- 탭 이름·내부 연결에 쓰는 군 값·집계 기준은 유지한다. 군 표시만 짧게 바꿔서 군 이동이나 집계가 달라지지 않게 한다.

### REQ-EVENTDAYWORKBOOK-009 등록경로 네 가지 단일 선택과 연결

- 전체 등록 명단과 각 군의 등록 구역에서 `직접방문`·`설문지`·`관계`·`교인인도` 중 하나를 선택한다. 선택하지 않은 빈칸도 허용한다.
- 선택한 값은 같은 관리번호의 전체 등록·군별 등록 명단에 함께 반영한다. 방문 명단에는 선택 칸을 만들지 않는다.
- 네 값 외의 입력은 저장하지 않고 셀 메모로 안내한다. 입력 행이 자동으로 늘어나거나 등록 구역이 이동해도 선택 목록을 유지한다.

### REQ-EVENTDAYWORKBOOK-010 소속이 다른 중복 명단 보존과 경고

- 이름과 정리한 휴대전화가 같아도 군 또는 팀이 다르면 두 행을 각각 보존한다. 한쪽 소속을 덮어쓰거나 행을 합치지 않는다.
- 같은 종류의 전체·군별 명단에 중복 확인 메모를 표시하고 이름 칸을 연한 노란색으로 강조한다. 집계는 남겨 둔 각 행의 관리번호를 기준으로 한다.
- 같은 종류의 명단에서 이름·휴대전화·군·팀이 모두 같으면 기존 입력에 연결한다. 전화번호 없는 동명이인은 합치지 않고 확인 메모를 남긴다.
- 이전 연결 방식 때문에 같은 관리번호가 다른 군의 확인 대기 행에도 남아 있으면, 이름·휴대전화가 같은 소속 차이만 새 관리번호로 분리해 보존한다. 바뀐 연결은 숨김 변경 기록에 남긴다.

### REQ-EVENTDAYWORKBOOK-011 방문 카드와 등록 카드의 기록 분리

- 같은 사람이 방문 카드와 등록 카드를 각각 제출하면 방문 1건·등록 1건으로 따로 센다. 한쪽 입력으로 다른 쪽 카드를 만들지 않는다.
- 전체 방문과 군별 방문만 같은 기록을 함께 사용한다. 전체 등록과 군별 등록도 별도로 같은 기록을 함께 사용한다. 방문과 등록 사이에는 정보 수정·군 이동·등록경로·삭제를 전파하지 않는다.
- 이름·정리한 휴대전화가 양쪽에 있으면 `방문·등록 각각 입력됨` 메모를 표시하고 새로 두 종류에 입력된 때 카드별 집계 안내를 띄운다. 같은 종류 안에서 소속이 다른 중복은 기존 노란색 경고를 유지한다.
- 기존에 방문·등록이 한 번호로 묶인 기록은 카드별 번호로 분리한다. 기존 명단과 처리 대기 중인 수정은 보존하고, 중간에 처리가 멈춰도 같은 카드를 여러 번 만들지 않는다.
- 운영자가 기존 방문 카드를 제외해 달라고 지정한 경우 그 방문 카드만 취소하고 등록 카드는 유지한다.

## 11. 테스트 사양

### TEST-EVENTDAYWORKBOOK-001 양방향 입력과 안전 경계

`tests/event-day-workbook.test.js`를 `node`로 실행하여 실제 `onEdit` 진입점에 가짜 Sheets 경계를 연결한다. 단순 명단의 방문·등록 입력 영역과 등록 단독 입력이 방문을 만들지 않는지와 이름을 비운 카드 종류의 전체·군별 명단에만 삭제가 전파되는지 확인한다.

전체→군, 군→전체, 방문·등록 카드 분리와 종류별 삭제, 군 이동, 여러 행 입력, 동일인 연결, 이름만 같은 사람 분리, 입력 검사, 서로 다른 항목 수정, 동일 항목 충돌, 미처리 입력 보존, 오류 후 복구, 이름 비우기를 확인한다.

실제 Google Sheets에서는 가상 인물로 양방향 입력·수정·등록 연결·군 이동·집계를 확인한 뒤 시험 자료를 제거한다. 로컬 검사는 권한과 Google의 편집 이벤트 전달을 대신 검증하지 않는다.

### TEST-EVENTDAYWORKBOOK-002 동시 입력과 중단 경계

### TEST-EVENTDAYWORKBOOK-003 분리된 Google Sheets 통합 검증
