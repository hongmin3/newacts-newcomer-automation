## 1. 목적

담당자가 일반 등록 명단과 등록 기간·주보 발행일을 선택하면 교적 후보를 대조하고, 확인한 명단으로 다음 주 주보를 준비한다. Windows에서 수동 실행하며 외부 저장 전에 담당자의 확인을 받는다.

기존 [구현 계획](../docs/superpowers/plans/2026-10-26-newcomer-administration.md)을 따른다. 사용자는 2026-11-08 일반 등록 시트를 기본 원본으로, 기등록자도 주보·새 번호·전도 실적에 포함하도록 확정했다.

## 2. 범위

기존 등록 보정·군 현황·방문 관리·교육·정착률은 변경하지 않는다. 예약 실행·메일 발송·Apps Script 배포는 추가하지 않는다. 운영 디모데에 신규 저장하는 시험은 금지한다.

주보 양식과 교적 저장 화면이 확인되지 않으면 해당 단계는 보류한다. 모의 실행 결과를 운영 완료로 표시하지 않는다. 원본의 기존 나이 열을 일괄 수정하지 않는다.

## 5. 요구사항

| 카테고리 | 이름 |
|---|---|
| ADMIN | Windows 교적·주보 업무 |

### REQ-ADMIN-001 원본 선정과 입력 검증

- **입력** 일반 등록 명단, 기간 시작·종료일, 주보 발행일을 지정한다. 날짜는 연도를 포함한다.
- **순서** 머리글 중복·누락, 필수값, 이름 구분자, 전화번호, 생년월일을 검사한다. 등록일로 정렬하며 같은 날짜는 원래 순서를 지킨다.
- **결과** 방문 전용은 제외하고 불확실한 입력은 검토 사유를 남긴다. 명단을 자동으로 합치지 않는다.
- **지킬 것** A열 번호·행 번호·이름·전화번호를 영구 식별자로 취급하지 않는다. 원본의 승인된 관리번호가 없으면 외부 쓰기는 보류한다. 출생연도만으로 생일을 만들지 않는다.

### REQ-ADMIN-002 교적 읽기와 동일인 대조

- **순서** 기존 HTTP 조회 코드의 전체 교인 검색을 이용한다. 검색 실패·쪽 누락은 신규 등록 근거가 아니다.
- **결과** 확인된 동일인, 신규 후보, 검토 대상으로 구분한다. 같은 전화번호의 다른 이름이나 생일 불일치는 자동 확정하지 않는다.
- **지킬 것** 이름 뒤 영문 구분자를 보존한다. 로그인은 한 번만 시도하며 실패 시 재시도하지 않는다. 읽기 모드에는 저장 기능을 전달하지 않는다.

### REQ-ADMIN-003 승인과 중단 복구

- **입력** 대상·날짜·정책·원본·교적 판정·양식 해시를 포함한 승인이다.
- **순서** 외부 요청 전에 시도를 SQLite에 저장하고, 결과를 다시 읽은 뒤 완료로 표시한다.
- **안 될 때** 저장 응답 유실이나 실행 중 강제 종료는 결과 불명으로 남긴다. 재조회 전 같은 저장을 반복하지 않는다.
- **지킬 것** 승인 뒤 입력 변경·부분 대상 선택은 새 승인이 필요하다. 다른 실행 묶음에서 같은 원본 인물을 다시 게시하지 않는다.

### REQ-ADMIN-004 주보 번호와 전도 실적

- **순서** 기준 주보 마지막 번호 다음부터 등록 순서대로 번호를 부여한다. 기등록자도 새 번호·주보·전도 실적에 포함한다. 방문자는 제외한다.
- **결과** 동일 인도자의 실적을 먼저 합산한다. 기존 9명에 2명이 더해지면 11명 위치에 한 번 기록한다.
- **지킬 것** 교역자는 인도 실적만 제외하며 등록자 총계는 별도 계산한다. 공란·스스로·공동 인도자·불명확한 교역자 식별은 담당자 결정 전 보류한다. 기준 총계와 마지막 번호가 다르면 초안을 확정하지 않는다.

### REQ-ADMIN-005 한글 작업 사본과 검증

- **입력** 선택한 한글 기준 파일과 확인된 양식 위치 정보다.
- **순서** 원본 해시를 확인하고 저장소 밖 작업 사본을 편집한다. 저장 후 다시 열어 이름·번호·합계·인도 실적·글자색을 대조한다.
- **안 될 때** 양식 위치가 없거나 다르면 편집을 멈춘다. 표·페이지 넘침은 담당자 확인 전 최종 저장을 막는다.
- **지킬 것** 사용자 문서와 다른 영역을 보존한다. 지난주 빨간색 전체 제거는 하지 않는다. 수정한 이름의 강조만 반영한다.

### REQ-ADMIN-006 공유 저장과 변경 충돌

- **순서** 최종 승인한 초안만 지정 경로에 저장한다. 대상 파일이 처음 확인한 해시와 다르면 멈춘다.
- **안 될 때** 저장 실패·응답 유실은 초안을 보존하고 최종 파일을 다시 읽어 판정한다.
- **지킬 것** Excel은 수정하지 않는다. 기존 최종본 교체는 별도 승인과 백업이 필요하다. 실물 카드 전달은 사람이 확인한다.

### REQ-ADMIN-007 Windows 실행과 개인정보 보관

- **결과** 전용 Python 환경과 수동 실행기를 제공한다. 현재 폴더와 관계없이 실행된다.
- **지킬 것** 인증·명단·후보·DB·주보는 저장소 밖 사용자 폴더에 둔다. 비밀은 Windows 현재 사용자 DPAPI로 암호화하고 사용자 폴더 접근 권한을 제한한다. 파일 잠금으로 동시 쓰기를 막고 DB 연결을 닫는다.

### REQ-ADMIN-008 운영 변경 시험 차단

- **순서** 모의 환경·운영 읽기·한글 시험 사본을 구분한다. 확인된 로그인·검색 요청만 운영 읽기에서 허용한다.
- **지킬 것** 알 수 없는 요청·교적 저장·삭제·변경 GET·다른 주소로의 이동은 전송 전에 차단한다. 실제 저장 화면·필드·성공 후 조회를 확인하기 전 운영 writer를 활성화하지 않는다.

## 11. 테스트 사양

### TEST-ADMIN-001 합성 자료와 로컬 경계

`newcomer-administration/tests/run_tests.py`에서 기간·입력 오류·동일인 충돌·승인 변경·응답 유실·중복 게시·주보 계산·원본 보존·저장 충돌·Windows 잠금을 확인한다. 외부 운영 설정은 읽지 않는다.

### TEST-ADMIN-002 지정 PC와 한글 사본

담당자 Windows 계정에서 실행기·사본 열기·저장·재열기와 공유 시험 폴더를 확인한다. 운영 디모데의 읽기와 모의 교적 저장 결과를 구분해 `progress.md`에 기록한다. 이 수동 절차는 자동 시험 통과를 뜻하지 않는다.
