이 문서는 `newacts-newcomer-automation`의 **디모데 자동 로그인 조회** 기능이 어떻게 동작해야 하는가를 정의한다.

공통 사양(시스템 구성·전체 흐름·비기능·데이터·설정·오류·보안)은 상위 `SPEC.md`에 있고 여기서 되풀이하지 않는다.
절 번호는 상위 문서와 같은 뜻이다. 빠진 번호(3·4·6~10)는 공통 사양이라 상위 문서에 있다.

파일 경로는 모두 프로젝트 루트 기준으로 적는다(`specs/` 기준이 아니다). 검사기도 루트 기준으로 확인한다.

## 1. 목적

담당자나 AI 작업자가 디모데의 교인 소속·등록일을 확인해야 할 때, 브라우저를 띄우거나 사람이 로그인하지 않고 바로 읽어 온다. 성공 조건은 Mac 키체인에 저장한 계정으로 로그인해 이름이나 전화번호 검색 결과를 빠짐없이 돌려주는 것이다.

### 이 기능은

- 새가족 명단 정리, 군·팀 확인, 등록일 확인처럼 디모데를 읽어야 하는 작업에서 쓴다.
- 이름 또는 전화번호를 넣으면 검색된 교인의 이름·등록일·교인구분·올해 소속을 돌려준다. 원본 명단 행을 넣으면 같은 사람인지 판정한 결과를 돌려준다.
- 같은 사람으로 확정할 수 없는 경우는 추측하지 않고 `check`(사람 확인 대상)로 돌려준다. 담당자가 이 목록을 보고 결정한다.

### 이 기능에서 쓰는 말

| 용어 | 뜻 |
|---|---|
| 키체인 항목 | Mac 키체인에 서비스 이름 `kr.newacts.settlement`로 저장한 디모데 계정과 암호 |
| 교인구분 필터 | 디모데 검색 화면의 `교인 > 청년` 같은 조건. 기본은 청년만 보여 준다 |
| 올해 소속 | 검색 결과 카드의 붉은 글씨 `명군 > 하이 > 리더` 줄. 군과 팀만 쓴다 |

## 2. 범위

### 포함

- 키체인 계정으로 디모데에 로그인하기
- 이름·전화번호로 교인 검색하기(결과 여러 쪽 포함)
- 원본 명단 행과 디모데 교인이 같은 사람인지 판정하기
- 결과를 화면(표준 출력)에 JSON으로 내보내기

### 제외

- 디모데 교적의 등록·수정·삭제. 이 기능은 저장 버튼이나 수정 화면을 열지 않는다.
- 출결 읽기와 정착률 계산(`specs/settlement-desktop.md`의 범위)
- Google Sheets 쓰기와 메일 발송
- 계정·암호를 키체인에 넣는 일. 담당자가 직접 `security add-generic-password`로 저장한다.

### 요구사항 지도

1. 로그인: REQ-DIMODELOOKUP-001
2. 검색: REQ-DIMODELOOKUP-002
3. 동일인 판정: REQ-DIMODELOOKUP-003
4. 결과 내보내기: REQ-DIMODELOOKUP-004

### REQ-DIMODELOOKUP-001 키체인 자동 로그인

- **하는 일**: 사람이 로그인 화면에 입력하지 않아도 디모데에 로그인한다.
- **입력**: 계정 이름은 `--account`, 환경 변수 `NEWACTS_DIMODE_ACCOUNT`, 키체인에 저장된 항목 하나의 순서로 정한다.
- **순서**:
  1. 키체인 서비스 `kr.newacts.settlement`에서 계정의 암호를 읽는다.
  2. 로그인 화면을 받아 숨은 입력값을 그대로 담고 계정과 암호를 보낸다.
  3. 응답 주소가 다시 로그인 화면이면 실패로 본다.
- **안 될 때**: 키체인 항목이 없거나 여러 개인데 계정을 정하지 않았으면 저장 방법을 안내하고 멈춘다. 로그인에 실패하면 다시 시도하지 않고 멈춘다.
- **지킬 것**: 암호를 화면·파일·로그·오류 문장에 남기지 않는다. 계정과 암호를 저장소에 쓰지 않는다.

> **주의** 같은 암호로 계속 시도하면 계정이 잠길 수 있다. 실패 후 자동 재시도는 하지 않는다.

### REQ-DIMODELOOKUP-002 읽기 전용 교인 검색

- **하는 일**: 이름이나 전화번호로 디모데 교인 검색 화면의 결과를 모두 읽는다.
- **순서**:
  1. 검색할 때마다 빈 검색 화면을 새로 받는다.
  2. 이름 칸이나 휴대전화 칸 하나에만 값을 넣어 검색한다.
  3. 결과 화면의 검색 칸 값이 요청한 값과 같은지 확인한다. 다르면 오류로 멈춘다.
  4. 결과가 여러 쪽이면 모든 쪽을 읽는다. 쪽을 넘겨도 새 교인이 나오지 않으면 오류로 멈춘다.
- **설정**: 기본은 `교인 > 청년` 필터를 그대로 쓴다. `--all-states`이면 교인구분 필터를 비워 장년·새가족에서 넘어온 사람도 찾는다.
- **결과**: 교인마다 디모데 번호, 화면 이름, 비교용 이름, 휴대전화, 생년월일, 등록일, 교인구분, 올해 소속(군·팀) 목록을 돌려준다.
- **지킬 것**: 로그인과 교인 목록 화면에만 요청한다. 교인 수정 화면을 열거나 저장 요청을 보내지 않는다. 결과가 15쪽을 넘으면 읽지 않고 `check`로 돌려준다.

> **예시** 장년부에서 등록해 청년부로 넘어온 사람은 청년 필터로 검색하면 다른 군의 동명이인만 나왔다. 교인구분 필터를 비우자 `교인 > 새가족`으로 등록된 본인(조군 보배)이 나왔다.

### REQ-DIMODELOOKUP-003 동일인 판정

- **하는 일**: 원본 명단의 한 사람(이름·휴대전화·생년월일·군·팀)이 디모데의 누구인지 정한다.
- **순서**: 전화번호가 있으면 전화로 먼저 검색하고, 아래 순서로 처음 한 명이 남는 조건을 쓴다.
  1. 전화와 이름이 같고, 군·팀이나 생년월일도 같다.
  2. 전화와 이름이 같다. 생년월일이나 소속 차이는 오타나 이동으로 본다.
  3. 전화와 생년월일이 같고 이름만 다르다. 이름은 디모데 기준으로 쓴다.
- 전화로 정하지 못하면 이름으로 검색한다.
  1. 이름과 생년월일이 같은 사람이 한 명이다.
  2. 이름과 군·팀이 같고, 생년월일·전화가 서로 다르지 않은 사람이 한 명이다.
- 청년 필터로 같은 사람을 정하지 못하면 교인구분 필터를 비워 같은 규칙으로 한 번 더 찾는다. 장년·새가족에서 넘어온 사람을 찾기 위해서다.
- **결과**: `matched`(판정 방법·디모데 교인 포함) 또는 `check`(사유·후보 포함)를 돌려준다.
- **지킬 것**: 한 조건에 후보가 여럿이면 생년월일로 좁히고, 그래도 여럿이면 `check`로 둔다.

> **주의** 전화만 같고 이름과 생년월일이 모두 다르면 가족이 같은 번호를 쓰는 경우가 많다. 같은 사람으로 보지 않는다.

이름 끝의 동명이인 구분 영문자(`홍길동G`)와 띄어쓰기는 비교할 때만 뗀다. 결과의 화면 이름은 그대로 둔다.

### REQ-DIMODELOOKUP-004 결과 내보내기

- **하는 일**: 검색·판정 결과를 사람과 다른 도구가 읽을 수 있게 내보낸다.
- **결과**: `search`는 교인 목록, `match`는 행별 판정을 JSON으로 표준 출력에 쓴다.
- **지킬 것**: 결과에는 개인정보가 있으므로 저장소 안에 파일로 저장하지 않는다. 필요하면 사용자가 정한 저장소 밖 위치에만 둔다.

## 11. 테스트 사양

### TEST-DIMODELOOKUP-001 로그인·검색·판정 단위 검사

`settlement-automation/tests/test_dimode_lookup.py`를 실행한다. 가짜 HTML과 가짜 HTTP 응답으로 다음을 확인한다.

- 키체인 계정 고르기와 암호를 오류 문장에 넣지 않기
- 로그인 화면 입력값 담기와 로그인 실패 감지
- 검색 칸 값 확인, 여러 쪽 읽기, 교인 카드 읽기, 올해 소속 읽기
- 교인구분 필터 비우기
- 동일인 판정 다섯 가지 조건, 가족 번호 공유 거절, 후보 여럿일 때 `check`

실제 디모데 로그인과 검색은 운영 계정으로 한 번 실행해 결과를 읽어 확인한다. 단위 검사는 실제 디모데 화면 변경을 검증하지 않는다.
