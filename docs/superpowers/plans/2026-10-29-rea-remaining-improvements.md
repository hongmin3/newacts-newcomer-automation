# REA 잔여 개선 구현 계획

**Goal:** 교육 보고 누락과 신청 중복을 복구하고 운영 상태·배포 검증을 강화한다.
**Architecture:** 기존 프로젝트 경계를 유지한다. 교육은 숨김 처리 기록과 검토 목록을 사용하고, 신청은 제출별 단계 기록으로 중단 지점부터 이어간다.
**Tech Stack:** Apps Script, Node.js VM 테스트, Google Apps Script API.
**Spec:** SPEC.md REQ-EDU-001~004, REQ-INTENSIVE-001~002, REQ-SYNC-003.
**Global Constraints:** 기존 시트 열·메일 수신자·모드·예약 실행을 보존한다. 미리보기는 쓰지 않는다. 인증과 백업은 저장소 밖에 둔다.
**Shared Interfaces:** 처리 기록은 PREPARED → APPLIED → READY → SENT, 신청 기록은 RESERVED → ADMIN → PUBLIC → DONE. 상태 조회는 집계만 반환한다.
**Review Focus:** 쓰기 직후 예외, 재시도 중복, 원본 응답 재정렬, 미리보기 무변경, 운영 변경 충돌.

### Task 1: 교육 복구와 검토 재처리
- [x] 실제 처리 진입점을 가짜 Sheets로 실행하는 회귀 테스트를 추가하고 실패를 확인한다.
- [x] 보고 대기 기록을 출석 쓰기 전에 저장한다. 새 응답 없이도 대기 보고를 재시도한다.
- [x] 검토 목록과 해당 응답만 재처리하는 함수를 추가한다. 커서는 되돌리지 않는다.
- [x] 전화번호 중복·이름만 일치·기존 출석 보호·순서·미리보기를 검증한다.

### Task 2: 집중교육 신청 복구
- [x] 공개 쓰기 실패 후 동일 이벤트 재시도 테스트를 먼저 실패시킨다.
- [x] 관리자 숨김 기록에 제출 식별자와 쓰기 위치·단계를 예약한다. 재시도는 같은 위치에 쓰며 정렬을 반복해도 결과가 같다.
- [x] 다른 제출의 중복 의심, 유효하지 않은 신청 비공개, 쓰기 직후 실패를 검증한다.

### Task 3: 운영 도구와 검증
- [x] 배포의 잘못된 대상·운영 변경 충돌 테스트를 먼저 실패시킨다.
- [x] push 전 HEAD 비교와 백업·즉시 재확인, 배포 ID 지정·이전 버전 복구 정보를 구현한다.
- [x] 집계 상태 조회, 안내 문서, 전체 테스트와 운영 읽기 검증을 완료한다.
- [x] 새 검토자에게 전체 변경을 검토받고 중요한 문제를 수정한다.
- [x] 운영 반영 후 다시 읽어 대조하고 문서·게이트·커밋·푸시를 마친다.
