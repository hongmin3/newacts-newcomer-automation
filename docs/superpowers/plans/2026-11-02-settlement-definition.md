# 출석률·정착률 기준 개편 계획

기준: REQ-RATEDESKTOP-008. 기존 metrics·collect_results·시트·Qt 화면·메일·월별 이력의 연결을 확인했다. 새 프로그램을 중복 작성하지 않고 기존 모듈과 실행 파일을 확장한다. live 데이터와 인증은 local/에서만 다룬다.

1. 순수 계산: calendar 3개월 창, 개인 출석 횟수, 정착 상태, 전체 인원 분모의 집계를 실패 테스트부터 구현한다. 기존 rate는 출석률로 유지하고 settlement_rate는 새 지표다. 내부 recent4 필드는 과거 이력 호환용으로만 남긴다.
2. 수집 연결: 최근 3개월이 포함된 연도별 달력을 읽고 새 지표를 개인 결과와 CSV에 보존한다. 기존 합계 CSV는 새 정착률을 역산하지 않는다.
3. 표시 연결: 결과 탭·메일·앱은 출석률과 정착률을 구분하고 최근 4주 표시를 3개월 횟수로 바꾼다. 관리용 현황·월별 이력 탭은 새 이름으로 만들어 과거 탭을 보존한다. 돌봄 기록 열은 바꾸지 않는다.
4. 검증: Python 전체·Node 전체·준비 검사·독립 검토 후 더블클릭 실행 파일로 실제 재조회한다. 조회 부족은 잠정 집계로 저장한다. 운영 메일은 보내지 않는다.
5. 정리: CHANGELOG·progress·README·사양 HTML을 갱신한다. 원격 변경과 겹친 문서는 보존하여 통합하고 검증 뒤 커밋·푸시한다.

결정: 사용자 최신 요청의 전체 인원 분모를 적용한다. 관찰 중 제외라는 앞선 답은 최신 요청으로 대체된다. 달력상 3개월 양끝 포함, 등록일 이후 주일만 계산한다. 화면의 새 정착률에 누적 출석률을 재사용하지 않는다.

상태: 완료. 순수 계산·수집·표시·검증·운영 재조회와 결과 재확인을 마쳤다. 세부 실행 상태는 progress.md에 둔다.
