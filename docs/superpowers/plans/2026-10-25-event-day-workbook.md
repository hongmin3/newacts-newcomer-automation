# 11월 1일 행축 명단 구현 계획

사용자 확정: 빈 명단, 방문 이력 유지와 등록 연결, 2026-11-01 하루. 전체·각 군 양방향 입력은 원 요청대로 제공한다.

## 근거와 선택

기존 `registration-project/하반기 방문 관리.gs`는 기존 등록 명단에서 방문 명단으로 보내는 단방향이며 기간·메일·열 구성이 연결되어 있다. 새 파일에 적용하면 기존 운영 범위가 달라지므로 재사용하지 않는다. 원본 두 파일은 읽기 자료로만 쓰고 상반기 파일을 복사한 뒤 모든 명단을 비운다.

수식으로 군별로 보여 주면 군별 입력을 받을 수 없다. 파일 안의 편집 처리 함수와 관리번호를 사용한다. 개인 자료는 새 Google 파일에서만 보관한다. 원본·기존 배포·메일·실행 조건은 보존한다.

## 공유 형식

A:V는 관리번호·날짜·군·팀·순·이름·성별·나이·생년월일·휴대폰·주소·인도자·예배(부)·방문·등록·결신·등록경로·비고·확인사항·수정시각·버전·화면 비교값이다. 입력은 B:R, 이름은 F다. 사용자 추가 요청에 따라 머리글 1행, 입력은 2행부터다.

숨겨진 원본의 V는 취소 여부다. 화면 V는 각 항목의 마지막 반영값을 보관하여 다른 미처리 입력을 지키는 데 쓴다. 원본 수정은 잠금 안에서 처리하고, 기록을 먼저 저장한 뒤 필요한 화면만 맞춘다.

## 작업

1. 요구사항과 `onEdit` 경계 테스트를 먼저 작성하고 기능 부재로 실패하는지 확인한다.
2. `event-day-workbook/Code.gs`에 검사·저장·동일인 연결·부분 항목 수정·충돌·화면 반영·메뉴 복구를 구현한다. 편집 함수가 다른 파일을 열거나 메일을 보내지 않게 한다.
3. `layout.cjs`로 새 파일의 헤더·고정행·입력 검사·집계·안내를 구성한다. 12개 입력 탭은 같은 열을 쓴다.
4. 새 파일에 연결된 Apps Script를 작성하고 가상 인물로 실제 편집 흐름을 확인한다. 시험 명단·기록을 지운 후 빈 상태와 수식을 다시 읽는다.
5. 별도 검토, 자체 전체 테스트, 준비 검사와 워크스페이스 검사를 수행한다. 문서·사양 HTML을 갱신하고 이번 파일만 커밋·push한다.

## 검토 초점

같은 전화번호의 다른 이름, 전화번호 없는 동명이인, 여러 행 붙여넣기, 같은 항목 충돌, 화면 반영 실패, 군 변경 때 대기 중인 입력, 행을 직접 지운 뒤 복구를 확인한다.
