이 문서는 뉴액츠 새가족 자동화가 어떻게 동작해야 하는가를 정한다. 코드가 지금 그렇게 움직인다고 해서 그것이 사양이 되지는 않는다.

사양과 구현이 다르면 코드에 맞춰 이 문서를 고치지 않는다. SPEC / CODE MISMATCH 형식으로 알린다. 절차는 AGENTS.md에 있다.

1. 목적

새가족부 운영진이 새가족의 등록 → 교육 출석 → 수료 → 보고를 손으로 옮겨 적지 않고 운영하게 돕는 자동화다.

성공 조건은 두 가지다.

  • 출석 응답이 들어오면 사람이 손대지 않아도 교육 명단, 등록 명단, 수료현황이 서로 맞는다.
  • 주간 운영 판단에 필요한 명단과 통계가 정해진 시각에 담당자에게 메일로 도착한다.

자동으로 판단할 수 없는 건은 임의로 고치지 않고 검토 대상으로 보고한다.

이유 아무도 모르게 틀린 값을 쓰는 것보다 사람이 확인하도록 남기는 쪽이 항상 옳다.

2. 프로젝트 범위

포함

  • 새가족 교육 출석 입력 웹앱(본인 확인, 주차 확인, 응답 시트 기록)
  • Google Form 출석 응답 가운데 새로 들어온 것만 교육 출석 현황 시트에 반영
  • 집중교육 참석 결과를 교육 출석 현황에 합치기
  • 등록 명단의 군·팀·전화번호를 교육 출석 기준으로 자동 보정하고 군 현황판 갱신
  • 교육 출석과 등록 명단을 합친 수료현황 다시 쓰기, 주간 전체·군별 보고 메일
  • 토요일 문자공지 대상 명단(교육 진행 중 / 교육 미진행) 메일
  • 집중교육 신청 Form 접수, 관리자 명단과 공개 명단의 즉시 동기화
  • 실행 결과의 숨김 로그 기록과 메일 수신자 안전장치
  • 저장소 코드와 운영 Apps Script 코드를 맞추는 동기화 도구(scripts/apps-script.mjs)

제외

  • 실제 문자(SMS) 발송. 이 자동화는 발송 대상 명단과 번호 목록까지만 만든다.
  • 정착률 계산과 월간 정착률 메일. 외부 시스템에 로그인해야 해서 Apps Script로 실행할 수 있는 범위 밖에 있다(docs/settlement-monthly-email-analysis.md).
  • 개인 명단과 실행 결과 데이터를 저장소에 보관하는 일. 데이터는 Google Sheets에만 둔다.
  • 교육·등록 예약 실행(Apps Script 트리거)을 자동으로 만들거나 바꾸는 일. 이 일정은 Apps Script 화면에서 사람이 관리한다. 단, 집중교육 신청 설치 함수가 제출 때 실행되는 트리거를 만드는 일은 포함한다.
  • 운영 배포 자동화. 배포는 사람이 승인한 뒤 손으로 실행한다.

3. 시스템 구성

네 개의 서로 독립된 Apps Script 프로젝트로 이루어진다. 디렉터리 하나가 Apps Script 프로젝트 하나다.

같은 디렉터리의 .gs 파일은 전역 설정과 공통 함수를 함께 쓴다. 그래서 따로 떼어 독립 스크립트로 나누지 않는다.

구성 요소책임위치
출석 웹앱교육 참석자 본인 확인, 주차 확인, 응답 시트 기록attendance-webapp/
교육 관리새 응답 반영, 집중교육 합치기, 문자공지 명단, 교육 메일 발송 관문education-project/
등록·보고등록 정보 자동 보정, 군 현황판, 수료현황, 주간 보고 메일, 결산registration-project/
집중교육 신청Form과 관리자·공개 Spreadsheet 설치, 제출 때 즉시 동기화intensive-training-application/
동기화 도구저장소와 운영 코드 비교·가져오기·올리기·배포(diff/pull/push/deploy)scripts/apps-script.mjs
정적 검증Apps Script API를 부르지 않고 이 컴퓨터에서 돌리는 함수·소스 검사tests/

이 자동화가 바깥 시스템과 만나는 곳은 Google Sheets, Google Forms, Google Drive, MailApp, PropertiesService, LockService다. 모두 Apps Script를 실행하는 계정의 권한으로 접근한다.

저장소 쪽에서 바깥과 만나는 곳은 Apps Script API(scripts/apps-script.mjs)와 clasp가 저장한 refresh token 하나다.

4. 전체 동작 흐름

  1. 참석자가 출석 웹앱에서 이름·전화번호로 조회하고 이번 주차 출석을 낸다.
  2. 서버가 제출 값을 다시 확인한 뒤, 출석 응답 시트의 머리글 바로 아래(2행) 에 끼워 넣는다.
  3. 교육 프로젝트가 화요일 17:00~18:00에 한 번 실행된다. 커서 이후에 들어온 새 응답만 오래된 것부터 교육 출석 현황에 반영하고, 결과를 메일과 숨김 로그로 남긴다.
  4. 등록 프로젝트가 월요일에 교육 출석을 기준으로 등록 명단의 군·팀·전화번호를 보정하고 군 현황판을 다시 쓴다. 사람이 직접 고친 값은 보호한다.
  5. 등록 프로젝트가 금요일에 등록 명단과 교육 출석을 전화번호로 묶어 수료현황을 다시 쓴다. 그리고 전체 관리자와 군 담당자에게 주간 통계를 보낸다.
  6. 교육 프로젝트가 토요일에 문자공지 대상 명단과 번호 목록을 메일로 보낸다.
  7. 집중교육 신청은 위 흐름과 따로 돌아가는 독립 프로젝트다. Form이 제출되면 곧바로 관리자 명단과 공개 확인 명단을 갱신한다.

  • 등록 명단의 각 줄을 교육 출석 원본 응답과 매칭한다. 판단 순서는 ① 저장된 매칭 이름 ② 현재 이름과 전화번호 ③ 등록 명단에서 하나뿐인 이름이다. 최신 응답을 앞세운다.
  • 자동으로 보정하는 항목은 군·팀·전화번호다.
  • 이름은 자동으로 보정하지 않는다. 등록 명단의 이름과 교육 출석의 이름이 다르면 검토 내역으로 보고하고, 어느 쪽이 맞는지는 사람이 확인한다.
  • 값이 다르면 교육 쪽 최신 값으로 보정한다. 보정한 값과 바로 전 값은 스크립트 속성에 기록한다.
  • 다음 실행에서 현재 값이 바로 전에 자동 보정한 값과 다르면 사람이 고친 것으로 본다. 그 항목은 보호 대상으로 바꾸고, 이후 자동으로 고치지 않는다.
  • 이미 보호 대상인 항목은 값이 달라도 건드리지 않고 보호 내역으로만 보고한다.
  • 결과 메일에는 다음을 담는다.
    • 건수: 등록자, 매칭, 미매칭, 자동수정, 수동수정 보호, 검토
    • 자동수정 상세: 행 / 이름 / 항목 / 기존값→교육 최신값 / 판단 근거
  • 결과 메일은 정기 실행 때도 테스트 수신자 한 명에게만 간다. 관리자 전체에게 보내도록 바꾸려면 그 자체를 사양 변경으로 다룬다.
  • 미리보기와 테스트 실행은 시트를 바꾸지 않는다.

  • 스크립트 속성은 등록자 수만큼 하나씩 읽고 쓰지 않는다. 한 번에 읽고 한 번에 저장한다.
  • 응답 시트 전체를 읽되, 커서 이후 응답만 반영한다(REQ-EDU-001).

9. 오류 처리 정책

  • 교육 새 응답 처리의 범위는 저장된 커서로 정한다.
  • 시트, 커서, 로그, 메일은 한꺼번에 성공하거나 한꺼번에 취소되는 한 묶음(트랜잭션)이 아니다. 그래서 어느 단계에서 실패했느냐에 따라 다음 실행이 복구하지 못하는 작업이 있을 수 있다. 실패하면 커서와 시트에 반영된 상태를 확인한다.
  • Apps Script 트리거 실패 알림은 Apps Script 설정에 맡긴다.
  • 부분 성공을 허용한다. 자동으로 판단할 수 있는 줄만 반영한다. 나머지는 시트를 바꾸지 않고 검토·중복·충돌로 나눠 메일과 숨김 로그에 남긴다. 검토 항목을 짐작으로 자동 수정하지 않는다.
  • 멈춰야 하는 조건은 다음과 같다.
    • 필요한 시트나 스프레드시트를 찾지 못한 경우
    • 잠금을 얻지 못한 경우
    • 메일 수신자 안전장치를 어긴 경우
    • 웹앱 입력 확인에 실패한 경우
    • 웹앱에서 요청한 주차가 기존 기록과 맞지 않는 경우
    • push 뒤 다시 확인했을 때 다른 경우
    • 집중교육 설치 확인에 실패한 경우(만든 것을 정리해 본 뒤 멈춘다)
  • 아무 일도 하지 않고 정상으로 끝나는 조건
    • active가 거짓
    • 새 응답 0건
    • 처리 기준 커서가 없어 초기화가 필요한 경우
  • 기록 위치
    • 실행 요약: 각 스프레드시트의 숨김 로그 시트
    • 상세: 결과 메일
    • 예외와 진행 로그: Apps Script 실행 로그
  • 미리보기 함수는 어떤 실패 경로에서도 시트·속성·메일을 바꾸지 않는다.

10. 보안 요구사항

  • 인증 수단은 두 가지다.
    • Apps Script 실행 계정의 권한(시트·메일·드라이브)
    • 로컬 동기화 도구가 다시 쓰는 clasp refresh token. 토큰 파일은 사용자 홈 폴더에만 두고 저장소에서 뺀다.
  • 저장소에 들어가면 안 되는 값: 개인 명단, 실행 결과, 인증 토큰, 개인 절대경로.
  • 스프레드시트·스크립트 식별자는 운영 코드에 필요한 만큼만 두고, 이 사양 문서에는 쓰지 않는다.
  • 출석 웹앱은 로그인 없이 누구나 열 수 있다. 다만 실행 권한은 배포한 사람의 계정이고, 조회할 때 이름과 전화번호를 모두 요구한다.
  • 다른 웹페이지 안에 넣어 보여 주는 것(외부 iframe 임베드)은 허용하지 않는다.
  • 사용자 입력을 HTML에 넣기 전에 이스케이프한다.
  • 집중교육 관리자 파일은 비공개이고, 공개 확인 시트만 링크 뷰어 권한이다(NFR-SEC-001).
  • 운영 수신자, 시트 식별자·이름·열 위치, 트리거 함수 이름, active, mode는 근거 없이 바꾸지 않는다.
