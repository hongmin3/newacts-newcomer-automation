# 출석 웹앱 고도화

## 해결한 운영 위험

- 기존 웹앱은 새 응답을 2행에 삽입했지만 교육관리 자동화는 마지막 처리 행 이후만 읽었다. 신규 출석이 처리되지 않을 수 있으므로 새 응답을 시트 끝에 추가하도록 통일했다.
- 서버 측에서 이름, 전화번호, 주차, 군·팀을 다시 검증한다.
- 스크립트 잠금과 동일 주차 확인으로 연속 클릭·동시 요청의 중복 출석을 방지한다.
- 기존 이력의 다음 주차만 제출할 수 있게 해 클라이언트 값 변조를 차단한다.
- 사용자 이름을 HTML에 넣기 전에 이스케이프한다.
- Apps Script 호출 실패 처리기를 추가해 로딩 화면에 멈추지 않게 한다.
- 외부 iframe 허용 설정을 제거한다.

## 배포 순서

1. 현재 교육 응답 마지막 행과 `EDUCATION_LAST_RESPONSE_ROW`를 확인한다.
2. 웹앱 서버·화면 코드를 저장하고 새 버전으로 배포한다.
3. 테스트 인물로 조회만 수행해 기존 주차와 군·팀 표시를 확인한다.
4. 승인된 테스트 출석을 한 건 제출한다.
5. 교육 자동화 미리보기에서 신규 마지막 행 한 건이 감지되는지 확인한다.
6. 교육 자동화를 TEST 모드로 실행해 시트 반영 및 본인 테스트 메일을 확인한다.
7. 중복 제출이 새 행을 만들지 않는지 확인한다.
8. 운영 모드와 기존 운영 수신자를 복원하고 트리거를 활성화한다.
