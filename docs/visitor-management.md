# 하반기 방문 관리 안내

10월 4일부터 등록한 새가족을 하반기 방문 명단에 반영하고, 10월 31일·11월 1일 행사 준비와 등록 현황을 함께 확인합니다. 현재 운영 반영 여부는 [progress.md](../progress.md)를 먼저 확인하세요.

## 영향 범위

| 대상 | 변경 내용 | 확인 방법 |
|---|---|---|
| 등록 프로젝트 월요일 실행 | 등록 보정·군 현황 다음에 방문 반영·행사 집계 추가 | 기존 `runAllAutomationTrigger` 경로 테스트와 운영 미리보기 |
| 하반기 방문 명단 A:O | 신규 등록자 추가, 기존 방문자의 빈 N열에 O 표시 | 이름·전화번호·등록일·추가/갱신 목록 확인 |
| 하반기 집계 R:T | 선방문·문화행축·행사 날짜를 모든 군에 같은 기준으로 적용. 군이 비거나 다른 표기이면 별도 확인 건수로 보고 | 날짜 경계·중복 제외 테스트와 운영 반영 후 수식 계산 결과 확인 |
| Q열 군 이름·U열 목표 | 기존 값 보존 | 반영 전후 비교 |
| 월요일 결과 메일 | 방문 반영, 관리 기간, 군별 기록, 행사 기록, 검토 내역 추가 | 텍스트·HTML 본문 검사. 기존 한 명 수신 유지 |
| 시트 메뉴 | 방문 동기화·집계·현황·마감일 지정/해제 | 실제 메뉴 선택과 취소 확인 |
| 교육·수료·문자공지·정착률 | 방문 명단을 직접 읽는 연결 없음 | 기존 테스트 회귀 확인 |
| 기존 상반기 방문·상반기 결산 | 보관, 이 기능이 변경하지 않음 | 코드 대상 시트 확인 |

기존 상반기 결산 함수는 등록 명단을 읽어 상반기 결산을 계산합니다. 하반기 방문 관리의 마감은 이 함수를 호출하지 않습니다. 하반기 결산 시트를 따로 만들거나 기존 결산 기준을 바꾸는 일은 포함하지 않습니다.

## 운영 반영과 첫 확인

1. 등록 프로젝트 운영 코드가 저장소와 같은지 `node scripts/apps-script.mjs diff registration`으로 확인합니다.
2. 승인한 변경을 등록 프로젝트에 반영합니다. 이 프로젝트는 웹앱이 아니므로 웹앱 버전을 새로 배포할 필요는 없습니다.
3. 편집기에서 `previewVisitorManagement()`를 실행합니다. 추가·등록 표시·검토 건수와 관리 기간을 확인합니다. 시트·속성·메일은 바뀌지 않습니다.
4. 시트를 다시 열어 메뉴의 `방문자 명단만 동기화`를 선택합니다. 방문 명단과 R:T 집계가 함께 갱신됩니다. 이 메뉴는 메일을 보내지 않습니다.
5. 첫 월요일 실행 결과에서 방문 항목과 시트 결과를 대조합니다. 새 실행 시점은 만들지 않습니다.

> **주의** `runRegistrationMaintenanceTest()`는 시트를 바꾸지 않지만 한 명에게 메일을 보냅니다. 실제 발송 확인은 승인한 범위에서만 합니다.

## 관리가 끝날 때

1. `방문 관리 현황·마감 확인`으로 미반영·검토 건수를 확인합니다.
2. 필요한 등록 입력을 마치고 방문자 명단 동기화를 실행합니다.
3. `방문 관리 마감일 지정`에서 마지막 관리 날짜를 `YYYY-MM-DD`로 적습니다. 시작일 이후의 실제 날짜여야 합니다.
4. 마감일을 저장한 뒤 다시 동기화해 집계 수식에도 마감 범위를 적용합니다. 기간 안의 늦은 등록 입력은 다음 실행 때도 반영됩니다.
5. 검토 대상은 담당자가 원본 등록과 방문 명단을 비교해 확인합니다. 기존 명단과 수식은 보관합니다.

마감일을 해제할 때는 `방문 관리 마감 해제`에서 확인합니다. 해제 후 다시 동기화하면 종료일 미정 집계로 돌아옵니다. 마감일 저장·해제 자체는 방문자 명단을 지우거나 메일을 보내지 않습니다.

## 검증의 범위

`tests/visitor-sync.test.js`는 실제 Apps Script 코드를 메모리 시트·속성·메일 대체 환경에서 실행합니다. 날짜 경계, 중복·불일치, 기존 기록 보호, 재실행, 마감 메뉴, 정기 실행의 메일 연결을 확인합니다. 실제 Sheets 수식 계산·권한·메일 도착·예약 실행은 운영에서 별도로 확인해야 합니다.

이 문서는 운영 절차와 영향 범위를 설명합니다. 현재 동작 기준은 [SPEC.md](../SPEC.md)의 REQ-VISITOR-001~004입니다.
